## 1. Overview & Measurement Philosophy

RevenueOS enforces a strict, non-hallucinatory semantic layer aligned with GAAP and IFRS commercial accounting standards. Every metric is computed deterministically in in-memory Pandas DataFrames and synthesized into standard Power BI DAX formulas.

No metric may be defined without:
1. An unambiguous mathematical formula.
2. Explicit Kimball dimensional grain.
3. Edge-case handling rules (e.g., zero revenue, negative quantities, null discounts).
4. Direct DAX implementation.

## 2. Top-Line Financial Metrics

### 2.1 Gross Revenue (Gross Sales)
* **Definition**: Total invoiced sales value generated by customer orders before any deductions, discounts, allowances, or returns.
* **Grain**: Fact Table (`orders`), row level.
* **Mathematical Formula**:
  $$\text{Gross Revenue} = \sum (\text{Quantity} \times \text{Unit Price})$$
* **Edge Cases**:
  - If `Quantity` $\le 0$: Flagged by Quality Check as return/credit memo or invalid transaction; excluded from forward gross sales.
  - If `Unit Price` is null: Imputed from `dim_product.standard_price` or marked for manual reconciliation.
* **DAX Expression**:
  ```dax
  [Total Revenue] = 
  SUMX(
      orders, 
      orders[quantity] * orders[unit_price]
  )
  ```

---

### 2.2 Net Sales (Net Invoiced Revenue)
* **Definition**: Actual invoiced revenue realized after deducting volume discounts, promotional coupon vouchers, and trade allowances, prior to return refunds.
* **Mathematical Formula**:
  $$\text{Net Sales} = \sum \left( \text{Quantity} \times \text{Unit Price} \times (1 - \text{Discount Rate}) \right)$$
* **Discount Normalization**:
  - If `Discount Rate` $> 1.0$ (e.g., $15$ meaning $15\%$): Automatically normalized to $0.15$.
  - Clamped to $[0.0, 1.0]$. Negative discounts are clamped to $0.0$.
* **DAX Expression**:
  ```dax
  [Net Sales] = 
  SUMX(
      orders, 
      orders[quantity] * orders[unit_price] * (1 - orders[discount])
  )
  ```

---

### 2.3 Net Recognized Revenue (Final Top-Line)
* **Definition**: Total economic inflow recognized after subtracting customer refunds and cancelled transactions.
* **Mathematical Formula**:
  $$\text{Net Revenue} = \text{Net Sales} - \text{Return Value}$$
* **DAX Expression**:
  ```dax
  [Net Recognized Revenue] = [Net Sales] - [Total Returns Value]
  ```

## 3. Cost & Profitability Metrics

### 3.1 Cost of Goods Sold (COGS)
* **Definition**: Direct manufacturing, wholesale acquisition, or direct supplier costs incurred to fulfill delivered units. Excludes marketing and general administrative overhead.
* **Mathematical Formula**:
  $$\text{COGS} = \sum (\text{Quantity} \times \text{Unit Cost})$$
* **DAX Expression**:
  ```dax
  [Total COGS] = 
  SUMX(
      orders, 
      orders[quantity] * RELATED(products[unit_cost])
  )
  ```

---

### 3.2 Gross Profit
* **Definition**: Residual financial contribution from sales after direct product procurement and fulfillment costs.
* **Mathematical Formula**:
  $$\text{Gross Profit} = \text{Net Sales} - \text{COGS}$$
* **DAX Expression**:
  ```dax
  [Gross Profit] = [Net Sales] - [Total COGS]
  ```

---

### 3.3 Gross Margin Percentage
* **Definition**: Proportion of each revenue dollar retained after direct cost of goods. Key benchmark: $\ge 25.0\%$.
* **Mathematical Formula**:
  $$\text{Gross Margin \%} = \begin{cases} \frac{\text{Gross Profit}}{\text{Net Sales}} \times 100 & \text{if Net Sales} > 0 \\ 0.0 & \text{otherwise} \end{cases}$$
* **DAX Expression**:
  ```dax
  [Gross Margin %] = 
  DIVIDE(
      [Gross Profit], 
      [Net Sales], 
      0.0
  )
  ```

---

## 4. Volume, Transactional & Unit Economics

### 4.1 Total Orders & Units
* **Total Orders**: Distinct count of validated commercial invoice/order IDs.
  ```dax
  [Total Orders] = DISTINCTCOUNT(orders[order_id])
  ```
* **Total Units Sold**: Sum of physical units fulfilled.
  ```dax
  [Total Units] = SUM(orders[quantity])
  ```
* **Average Order Value (AOV)**:
  $$\text{AOV} = \frac{\text{Net Sales}}{\text{Total Orders}}$$
  ```dax
  [Average Order Value] = DIVIDE([Net Sales], [Total Orders], 0.0)
  ```
* **Units Per Transaction (UPT)**:
  ```dax
  [Units Per Order] = DIVIDE([Total Units], [Total Orders], 0.0)
  ```

## 5. Commercial Leakage & Risk Indicators

### 5.1 Return Rate Percentage
* **Definition**: Frequency of purchased items returned for refund or exchange.
* **Formula**:
  $$\text{Return Rate \%} = \frac{\text{Returned Units}}{\text{Total Sold Units}} \times 100$$
* **Severity Thresholds**:
  - $\le 3.0\%$: **NORMAL** (Healthy ecommerce baseline)
  - $3.0\% - 6.0\%$: **ELEVATED** (Supplier inspection recommended)
  - $> 6.0\%$: **CRITICAL** (Immediate SKU packaging and defect review)

---

### 5.2 Customer Health Score
* **Formula**:
  $$\text{Health Score} = 0.35 \times \text{Recency} + 0.35 \times \text{Frequency} + 0.30 \times \text{Monetary}$$
* **Tiers**:
  - $\ge 0.75$: **Healthy / Champion Account**
  - $0.45 - 0.74$: **Stable / Expansion Candidate**
  - $0.20 - 0.44$: **At-Risk / High Churn Probability**
  - $< 0.20$: **Dormant / Lost Account**

## 6. Time Intelligence Measures

All time intelligence functions rely on the dynamically generated `dim_date` table:

```dax
// Year-To-Date Revenue
[Revenue YTD] = TOTALYTD([Net Sales], 'dim_date'[date])

// Prior Month Revenue
[Revenue Prior Month] = CALCULATE([Net Sales], DATEADD('dim_date'[date], -1, MONTH))

// Month-over-Month Growth %
[MoM Growth %] = 
VAR CurrentRev = [Net Sales]
VAR PriorRev = [Revenue Prior Month]
RETURN
DIVIDE(CurrentRev - PriorRev, PriorRev, 0.0)
```
